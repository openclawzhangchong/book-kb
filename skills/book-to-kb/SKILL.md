# 书本 → 知识库（book-to-kb）

把一本书/一套理论做成"智能体可检索、可调用"的单文件 Markdown 知识库，并推送到 GitHub 仓库 `openclawzhangchong/book-kb`（书本知识库，区别于经验库 zhishiku）。完整方法论见仓库根目录 `整理方法论-SOP.md`，本 Skill 是其可执行版。

## 工作流（七步，照序执行）

### 1. 定位确认
问清/约定四件事：用途与人设、单文件还是多文件、字数目标（默认 **3 万字左右、上限 5 万**——用户提大字数时主动拦：轻量知识库 3–5 万是召回质量与体量的平衡点）、是否推送 GitHub。

### 2. 结构设计（五章骨架直接套用）
- 〇、总纲与使用说明（起源/体系/智能体三步定位法）
- 一、核心理论库（原理拆解+现代白话，6–8 节）
- 二、招式/方法库（主体：每条四要素=使用条件/操作步骤/话术模板/禁区）
- 三、场景范例库（情境→普通人→高手→拆解，可附变式提示）
- 四、调用规则与输出风格（场景路由表/人设语气/四段式回答模板/底线声明）

三条铁律：①每节三件套=标题/关键词(4-8个)/触发场景（RAG切片优化）；②80% 现代可执行 + 20% 原著点题，**历史案例降维成模式卡、一句话佐证，禁止讲故事**；③底线声明内建最高优先级（只载合法自保与正当博弈）。

### 3. 派子 Agent 撰写
general-purpose 子 agent，prompt 写明：格式硬约束（三件套/四要素/配比/字数区间/章节骨架）、分批 Write+Edit 追加防截断、写完自查 `wc -m`（不足扩范例、超出压缩）。

### 4. 主 Agent 审核（8 项清单，逐项过）
①字数区间（wc -m 实测）②三件套齐全 ③四要素齐全 ④编号连续无跳号（范例/招式最易乱）⑤交叉引用真实存在 ⑥历史案例没退化成讲故事 ⑦路由表完备且引用不与编号体系撞车 ⑧底线声明与应急流程在位。

### 5. 修复与复核
修复后必须复核：Grep 全部 `### 招式/范例` 标题验编号连续；重编号同步更新路由表全部引用；`wc -m` 复测。标题带情境名可保证 old_string 唯一、安全重排。

### 6. 入库推送（若用户要求）
- 成品复制到本地 `book-kb/` 目录
- README「收录书目」表格登记一行（书目/文件/字数/用途）
- 跑 `scripts/push_book_kb.py`（Git Data API 四步法：blob→tree→commit→PATCH ref；PAT 自动从 `~/.workbuddy/mcp.json` 的 github-pat Bearer 读取；脚本会自动建仓——已存在则跳过）
- commit message：`feat: 收录《书名》知识库（X万字符，理论X节/方法X条/范例X组）`

### 7. 交付终审
present_files 成品 → 汇报字数/结构表/审核修复清单/复核结果 → 等用户终审。

## 检查与脚本

- `scripts/push_book_kb.py`：建仓+四步法推送脚本，改头部 `REPO_NAME/DESC/TOPICS/SRC_DIR` 即复用
- 推送验证：脚本输出 commit sha + 仓库 URL；必要时 GET `/repos/{owner}/{repo}/contents` 核对文件
